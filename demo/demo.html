Proof-of-work demo¶

Paper: Cloud Bursting Rarely Pays for Demand Response in On-Premise GPU Clusters (IEEE CCGrid 2027).

This notebook re-runs small pieces of the project live and checks them against the stored results the paper uses. It only reads the existing data, model checkpoint, prediction files, results and paper files. It never writes to them.

  1. Data: the cleaned Microsoft Philly job log.
  2. Transformer live: the trained model predicts 5 randomly drawn test jobs, compared with the stored predictors.
  3. Simulator live: one grid event re-simulated from scratch, compared with the stored E1 result row.
  4. Checks: the test suites, the prediction-file checker and the simulator's baseline check (Table I).
  5. Reproducibility: where the paper's numbers come from.

How to run it: see demo/README.md.

1. Data: the Philly job log¶

The Microsoft Philly trace is a public log of about 117,000 deep-learning jobs on a shared GPU cluster (Aug-Dec 2017). Track 1 cleaned it into data/processed/philly_jobs.parquet, one row per job. Each job ends as Pass, Failed or Killed (cancelled). The chart shows why this matters for the paper: Failed and Killed jobs are a minority of jobs but use most of the GPU-hours. Holding back such a job during a grid event costs little useful work. The model is tested only on jobs submitted in the test window. (These counts are over the whole log. The paper's Section 2 uses only the simulated test-window jobs, so its shares differ.)

2. Transformer live: predictions for 5 random test jobs¶

The transformer reads a job's owner's last (up to 32) finished jobs plus the current job. It predicts the remaining runtime as three quantiles (p10, p50, p90) and the chance the job will fail (p_fail). Here we load the best saved checkpoint (runs/tf_v1/best.pt) and run it now, on the CPU, on 5 test examples. The examples are drawn with a fixed, printed seed (ml/config.py SEED), so nobody chose them by hand. Next to the live predictions we show the true outcome and the stored rows of two other predictors for the same job and elapsed time. last2 is the classic "average of the user's last two jobs" rule; lightgbm is a gradient-boosted-tree baseline. The last column checks that the live output equals the stored predictions/transformer.csv row the simulator used. Expect about 1e-6: the file was written on the GPU, this run is on the CPU, and float32 rounds slightly differently.

3. Simulator live: one grid event, re-run from scratch¶

The grid asks the cluster to cut its power by 20% for 2 hours (the paper's default event). We take the first event of that cell from the same event list E1 uses. We simulate the trace up to the event start and copy the cluster state there (the snapshot). From that one snapshot we run four futures:

  • baseline: no event;
  • delay-only: pause running jobs;
  • burst-only: move running jobs to rented cloud GPUs;
  • mix-p90: the paper's controller, mixing pausing, power capping and bursting, with the transformer's p90 runtime.

All runs use the transformer predictions with the hold-beyond-grid rule. The target P* is 80% of the baseline's mean power during the event. The cost is $ per MWh shed (cloud bill + delay cost, w_f = 0). At the end we compare every number with the stored row in results/e1/runs.csv.

from flex.cloud import Cloud
from flex.engine import Engine
from flex.experiments import DEFAULT_EVENT, cell, load_setup
from flex.metrics import compliance
from flex.models import load_config
from flex.policies import run_policy, world_from_config
from flex.power import PowerTracker
from flex.predictions import load_predictions
from flex.paired import run_base

t_sim = time.perf_counter()
cfg = load_config()
cfg, sim_jobs, pool, events = load_setup(cfg, "philly", quick=False)
ev = cell(events, *DEFAULT_EVENT)[0]
print(ev)
tf = load_predictions(PRED / "transformer.csv")
tf.lookup_rule, tf.missing_pred = cfg["lookup_rule"], cfg["missing_pred"]
print("lookup rule:", tf.lookup_rule)
world = world_from_config(cfg, tf)

eng = Engine(sim_jobs, pool, check_every=cfg["check_every"], cloud=Cloud(world.cloud))
eng.run_until(ev.t_start - 3600)                  # run the trace up to 1 h before the event ...
pre = PowerTracker(world.params); pre.attach(eng) # ... record baseline power for that hour ...
eng.run_until(ev.t_start)
eng.on_event = None
snap = eng.snapshot()                             # ... and copy the state at the event start

base = run_base(snap, ev, world.params, world.h_after_s)
runs, rows = {"baseline": base}, {}
for label, name, w in [("delay-only", "delay", world), ("burst-only", "burst", world),
                       ("mix-p90", "mix", dataclasses.replace(world, cost_quantile="p90"))]:
    rows[label], _, runs[label] = run_policy(snap, ev, name, w, "transformer", "predictor", cfg["seed"], base, return_runs=True)
print(f"simulation: {time.perf_counter() - t_sim:.0f} s")

            "delay_usd": r["cost_usd"] - r["cloud_usd"], "usd_per_mwh": r["usd_per_mwh"]}

4. Checks¶

5. Reproducibility: where the paper's numbers come from¶

No result in the paper is typed by hand. paper/figures/make_numbers.py reads the saved results and writes paper/numbers.tex, one LaTeX macro per number; the text uses only these macros. paper/figures/check_claims.py re-checks the abstract's claims against the results. Below are the first lines of the generated file. We do not run the full regeneration here.
